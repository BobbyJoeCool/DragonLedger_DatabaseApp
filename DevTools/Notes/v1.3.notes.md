## Key Design Decisions

- **Checkbox = Display toggle**: User explicitly requested that checking a box in Browse directly adds/removes items from the Display collection — no separate "Add to Display" button
- **localStorage persistence**: Display collection persists across sessions via localStorage, not React state — survives page reloads and navigation
- **Snapshot caching in useSyncExternalStore**: `getSnapshot` must return the same reference when data hasn't changed; without caching, `JSON.parse` creates new array references each call, causing infinite re-render loops
- **Name resolution via parameter passing**: Instead of a complex resolver/cache pattern, item names are passed directly through the SelectionState interface methods (toggle accepts optional name, selectAll/selectPage accept optional name maps)
- **Print page breaks per type**: `break-before: page` on each `<section>` after the first ensures each content type starts on a new page when printing

## Issues Encountered

- **Infinite re-render loop**: `useSyncExternalStore` with `JSON.parse` in `getSnapshot` caused "Maximum update depth exceeded" because each call returned a new array reference. Fixed by caching the parsed result and comparing the raw localStorage string.
- **PORT conflict**: `preview_start` injects `PORT=5173` into the environment, overriding the `.env` `PORT=3000`. The Express server then started on 5173 (same as Vite), causing proxy failures. Fixed by wrapping the npm command with `env PORT=3000` in launch.json.
