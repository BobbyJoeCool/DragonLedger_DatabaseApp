# DragonLedger DatabaseApp — Post-v1.0.0 Roadmap (Draft)

**Status: draft punch list, not yet scoped.** v1.0.0 shipped — see
`Documentation/v1.0.0/v1.0.0-Roadmap.md` for the full build history. This
document captures the next four things to work on, as a starting point
for future design sessions, not a finished plan. Two of the four are real
feature work needing their own design pass (per this project's own
"ask first if more than one reasonable approach exists" rule); the other
two are process/tooling setup with no design ambiguity, just execution.

**Version numbering — open question.** Not yet decided whether this batch
of work ships as `1.1.0` (incremental, same product) or `2.0.0` (this
folder's own name). Whichever it is, `package.json` versions across all
four workspaces should move together, per the existing convention.

## 1. Initialize App Stylings

**What this likely means:** Phase 8 built a full theming system (Parchment /
Scribe's Copy / Grimoire) for the printable **card** views specifically —
the app's own chrome (sidebar, buttons, forms, the Browse table itself)
still uses the stock shadcn/Tailwind neutral theme, never deliberately
designed. This item is about giving the *app itself* a real visual
identity, not the cards.

**Open questions to resolve before building:**
- Does the app-chrome theme reuse/extend the existing card `--card-*`
  token system, or is it a fully separate design pass with its own tokens
  (the app's existing `--accent`/`--muted`/etc. shadcn tokens)?
- Is dark mode in scope, or just a single light theme?
- Any specific visual direction in mind, or does this start from a blank
  page (mood-board / reference session first)?
- Does this touch the Electron window chrome (title bar, traffic lights)
  at all, or CSS-only within the web content?

## 2. Add Multiple-Selection Feature

**What this likely means:** Browse currently only supports one record at a
time (click a row → navigate to its Detail view). This item is about
letting a user select *several* rows at once in the results table for some
bulk action.

**Open questions to resolve before building:**
- What's the actual bulk action this unlocks? Candidates: bulk delete,
  bulk "save as homebrew" copy, bulk export to JSON, or extending the
  existing Spell/Item trading-card print flow (currently filter-based, not
  row-selection-based) to other content types.
- Row-checkbox selection UI (a checkbox column in `ResultsTable`) vs. some
  other interaction pattern?
- All 8 content types, or scoped to specific ones first?
- Interacts with the existing virtualized/bidirectional infinite-scroll
  table (Phase 5) — does "select all" mean all *loaded* rows, or all rows
  matching the current filter (requiring the same `?fields=all` bulk-fetch
  pattern the trading-card feature already uses)?
